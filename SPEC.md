# Click-to-Call for NetSuite — Product & Behaviour Spec

A NetSuite SuiteApp (SDF, app id `com.netsuite.clicktocall`) that adds browser calling to NetSuite through Twilio. Reps call from Customer / Contact / Lead pages and take inbound calls in a dock on every page. Twilio records and transcribes the call. NetSuite's N/llm writes a summary, a satisfaction score, tone keywords and proposed follow-ups on the Phone Call record.

**Principle: no middleware, no NetSuite webhook.** Everything runs in SuiteScript (Suitelets, RESTlet, User Events, a Scheduled Script, a Portlet, a UIF SPA) and on Twilio's managed platform (TwiML App + one Twilio Function service for outbound TwiML (or the older hand-made TwiML Bin until it is published), Studio, Voice, Recordings, Conversational Intelligence). NetSuite reaches Twilio; Twilio never calls NetSuite. NetSuite learns about calls from the browser (fast path) and from a 15-minute poller (safety net).

**Status (2026-10-31):** sandbox `td3061543` (MFG 25.2 AI), branch `feat/telephony-dock`. Outbound, phone mode, dock, inbound routing and inbound recording are committed and live-tested. Call reconciliation (§7) and rep presence (§8) are built in the working tree, not yet committed or live-tested.

**How to keep this current:** update SPEC.md in the same commit as any behaviour change. When this file and the code disagree, the code is the truth; fix this file.

Paths: `F/` = `src/FileCabinet/SuiteApps/com.netsuite.clicktocall/`; `W/` = `src/SuiteApps/com.netsuite.clicktocall/setup_wizard/` (TypeScript source of the wizard bundle).

## 1. Phone mode shell & one anchor

**Purpose.** NetSuite page loads end WebRTC audio. A call must live in a page that never reloads.

**Current behaviour.**
- The shell Suitelet `customscript_ctc_sl_shell` is the tab's top page. It holds two same-origin iframes: `#ctc-ns-frame` (full-size NetSuite UI) and `#ctc-phone-frame` (the softphone Suitelet, hidden, `allow="microphone; autoplay"`). The phone frame is the only "anchor" that holds audio and call state. There is no popup anywhere.
- Frame start path comes from `u=`, validated by `safeFramePath`: must start with `/app/`, 1–2000 chars, no `//`, `\`, whitespace, control chars, scheme, or dot segments. Else the default `/app/center/card.nl?sc=-29`. The shell keeps the address bar in step (`history.replaceState` with `u=`).
- A shell loaded inside a frame replaces itself with its frame path (never nests).
- **Web Lock** `ctc-phone-anchor`, `ifAvailable`. Lock held → phone frame loads. Lock busy → no phone; the shell's dock is a **remote control** of the other tab's phone (§2; 2026-11-11, plan 1.10). Only when the dock is missing (its scripts failed; checked once the page is parsed, so it never flashes) the banner "Your phone is open in another tab" / "Use that tab for calls." (button Reload) shows instead. The waiting shell also queues a normal lock request, so it takes the phone by itself when the holder closes, crashes or is discarded (banner hides, phone starts). The first lock request fails (Web Locks present) → **bus probe**: the shell sends `hello` and starts the phone only when no working anchor (a snapshot with an `anchorId`, phase not `offline` / `moved`) answers within **1.5 s**; else the busy banner (lock `waiting`, no queued request: without a working lock this tab does not take the phone by itself).
- **One anchor (2026-11-11, review H2).** The softphone starts no Device and no bus host unless `window.parent.__ctcShell` exists (it says "Open phone mode to call" when opened any other way). Each anchor page load has a random `anchorId`; snapshots carry it and `locked` (its shell holds the lock). The anchor says `hello` at start. When an anchor sees another anchor's working snapshot, the one whose shell holds the lock wins (equal lock state: the lower `anchorId`); the winner answers with its snapshot, the loser unregisters, publishes `moved` and posts `ctc-phone-duplicate` to its shell, which stops the phone frame, frees the lock and waits with the busy banner. A loser in a live call steps aside only after the call ends. Docks put the latest working `anchorId` in each request as `anchor` (the shell sends no requests); an anchor drops a request that names another anchor, so one `dial` never makes two calls. Requests without `anchor` (old docks) are still accepted. The anchor publishes its id as `window.__ctcAnchorId` in the phone frame: the shell takes its `phase` (leave guard, banner text, Exit confirm, restart) only from its own phone's snapshots; another tab's call never turns on the leave guard here.
- **Reliable commands (2026-11-11, plan 1.10 f).** Every request carries `from` (the tab's sender id, one per page load, kept by the dock: `window.__ctcBusTab`) and `seq` (+1 per new command). The anchor runs each (`from`, `seq`) once: it keeps the last 32 seqs of the last 16 tabs; a repeat is dropped and acked again. Snapshots carry `acks` (`{ <from>: [last 8 seqs] }`) and `bus` (contract version, now **2**); the anchor publishes a snapshot after every request it ran. A request that reaches an anchor after it started to step aside (it lost to another anchor) is dropped, not run and not acked. Requests without `from` / `seq` (old docks) get no dedupe.
- **No hand-moved phone (2026-11-13, user decision).** The phone is present in every tab, so no tab moves the phone (or its audio) to itself: there is no takeover request, no "Move phone here" / "Use phone here" control and no `takeover=1` URL parameter, and the shell never steals the lock. The phone changes tabs only when the holder goes away (the waiting shell's queued lock request, above) or an anchor loses the one-anchor check. A holder whose lock is stolen anyway (another page, e.g. an older shell still open) stops its phone and waits — **except during its own live call**: lock `yielding`, the phone keeps the call (only the anchor ends a call), the anchor steps aside after the call (one-anchor rule), and the shell stops the phone frame when the call ends and waits. `__ctcShell.phoneState()` → `{ lock: 'none'|'held'|'waiting'|'yielding'|'disabled', audioUnlocked, notify }`; the shell calls `__ctcDock.refresh()` on every lock change.
- **Phone not enabled** — the anchor posts `ctc-phone-disabled` when the RESTlet answers `not_a_phone_user`: the shell releases the lock, stops the phone frame and shows "The phone is not enabled for your user. Ask your administrator." with **Exit phone mode**.
- **Audio + notifications unlock** — `audioUnlocked` = the tab had a user gesture (`navigator.userActivation.hasBeenActive`, a pointer / key event in the shell, or a 2 s poll that notices activation from NetSuite-frame clicks). Every unlock posts `ctc-unlock-audio` to the phone frame (it resumes Twilio's `AudioContext` and plays one silent sample: the ringtone can be blocked by autoplay until a gesture). `__ctcShell.unlockAudio()` (dock "Turn on phone" / "Get call alerts", §2) or a bus `unlockAudio` received while this tab has transient activation also calls `Notification.requestPermission()`, once. The shell sends `{ audioUnlocked, notify }` to the phone frame (`ctc-shell-state`) on phone-frame load and on change; the anchor puts both in the snapshot.
- **Inbound ring (away)** — the dock draws the incoming card (§2); the shell has no toast and no live region of its own. When the tab is hidden or the window unfocused during phase `incoming`: a system Notification (tag = call SID, `requireInteraction`, replaced when the caller name arrives) when permission is granted, and the title flashes "Ringing · <caller>" every 1 s; both stop when the phase leaves `incoming`, and the flash stops when the rep comes back. A notification click → `window.focus()` + `window.__ctcDock.focusIncoming()` (focuses the card's Answer, or the panel's Answer when the panel is open).
- `debug=1` on the shell URL is passed on to the softphone URL (Twilio SDK log level 1) and kept by `history.replaceState`.
- **Browser gate (2026-11-11, review H3).** At start the shell tests three APIs. Missing **Web Locks** or **BroadcastChannel** → no phone and no lock request; banner "This browser cannot run the NetSuite phone" / "It lacks <API>. Use a current version of Chrome, Edge, Firefox or Safari." with **Exit phone mode**. Missing **Navigation API** → **phone tab**: the shell drops the NetSuite frame (blanked, hidden; no navigation trap, no frame watcher, no screen-pop) and shows a card "This tab is your phone" ("Keep this tab open to make and take calls. Work in NetSuite in other tabs. The phone button on those pages controls this phone.") with the reason line and **Open NetSuite in a new tab** (opens the `u=` page with `_blank`). The phone, lock, bus, busy banner and Exit work as in framed mode (no frame banners; Sign in reloads the phone tab); title "Phone — NetSuite"; `__ctcShell.phoneTab` = true. Normal tabs drive the phone with the remote-control dock (§2). The dashboard auto-enter turns that dashboard tab into the phone tab.
- **Phone tab by admin switch (2026-11-11, review H1).** Config `custrecord_ctc_phone_tab_mode` (console Twilio account → Danger zone, §10) makes every shell a phone tab, in any browser: the server writes no NetSuite frame at all and `CFG.phoneTab` is true (no reason line on the card). The fallback when a NetSuite release breaks NetSuite inside the frame (framing policy, `top` use, flows). Read with `readPhoneTabMode` (lookupFields; any error → framed). Open shells switch at their next load. Not changed: docks, the portlet loader and the record Call button still move the current tab into the shell ("Open phone"), so that tab becomes the phone tab.
- **Navigation API:** NetSuite's Redwood menu calls `top.location.replace()`. The shell cancels cancelable same-origin `/app/` push/replace navigations and loads them in the frame. Not touched: browser-UI navigations, reloads, back/forward, login pages, other origins, the shell URL, Exit, and **top-level form posts** (`e.formData`: loading them in the frame would turn the POST into a GET; the tab leaves phone mode instead, logged `top post left alone`; 2026-11-11, review R13).
- Login page in the frame (session timeout) → frame blanked, **no banner** (asset 37: the pill, the panel's Signed out card and NetSuite's own modal say it); the shell posts `ctc-session-check` to its phone frame, which runs `sessionPing` at once, so the dock shows `signed_out` within a second or two. **An unreadable (cross-origin) page** (the sign-in host, another NetSuite account) → frame blanked, the same session check, and banner "This page cannot show inside phone mode" / "Reload to go back. If you were signed out, sign in again." (prefixed "Your call is still connected." during a call; 2026-11-11, review R12) with **Reload page**; a later phone `signed_out` or login page hides it, never the other way.
- **In-frame fixes (2026-11-11, review H4).** On each frame load the shell also listens to the frame's own Navigation API: a cancelable push / replace navigation to an http(s) origin that is not the account origin and not a `*.netsuite.com` host (and carries no form data) is cancelled and opened in a new tab (`window.open(url, '_blank', 'noopener')`, logged `external link`), so an external link no longer blanks the frame. **Print:** Ctrl / Cmd+P (no Alt / Shift) in the shell or in the frame prints the NetSuite frame (`contentWindow.print()`), not the shell; `__ctcShell.print()` does the same. The browser menu's Print still prints the shell (no API to redirect it). "Reload page" reloads only the NetSuite frame. **Sign-in again:** the dock's one **Sign in** (pill, panel card) calls `__ctcShell.reloadFrame()`, which loads the last good page in the NetSuite frame (never a new tab; the phone keeps its own frame, so a call stays up; the banner's Reload page does the same). The first normal (non-login) page the frame loads after a sign-out or the unreadable banner hides any banner and restarts the phone frame (`restartPhone`, loads the softphone URL again) when no call is live; during a live call the restart is skipped and the softphone recovers by itself (§3). **The restart is also skipped when the phone already recovered by itself** (its latest snapshot has no `session` / `signed_out` error and `canReceive` is not false; 2026-11-02, the soak test found a needless ~6 s gap). Before any snapshot the shell restarts. A login page after Reload marks the session lost again, with no restart.
- **Signed out (phone error kind `signed_out`, 2026-11-02; asset 37, 2026-11-14):** no shell banner (it hides an unreadable banner); when the tab is **hidden** at that moment and notifications are granted, one system notification "Signed out of NetSuite" / "Sign in again to keep receiving calls." (tag `ctc-signed-out`, `requireInteraction`), closed when the phone recovers.
- Both the shell and the softphone Suitelet send `Cache-Control: no-store, max-age=0` and `Pragma: no-cache` (`ctcHtml.setNoStoreHeaders`; a refused header never breaks the page).
- A `beforeunload` guard is on while this shell's own phone is in phase `incoming`, `dialing`, `ringing`, `answering`, `connected` or `reconnecting`.
- **Screen-pop: removed (2026-11-01, user decision).** Answering never navigates; the rep may be mid-task, and the panel's Open record link opens the record. The shell still accepts `ctc-open-record`, though nothing sends it: accepted only from `#ctc-phone-frame`, same origin, path `/app/common/entity/(custjob|contact).nl?id=<digits>`. `ctc-phone-disabled` and `ctc-phone-duplicate` are accepted from the same sender only.
- **Entry:** the dashboard portlet's dock loader auto-enters phone mode once when no tab holds the lock, sessionStorage `ctc-phone-exit` is not `'1'` and the phone is not marked not-enabled for this browser (localStorage `ctc-phone-not-enabled`, §2). Normal tabs show an "Open phone" chip, or the remote-control dock when another tab holds the phone (§2).
- **Exit phone mode** (dialer gear view, in the shell that holds the phone; not in a waiting shell or a remote tab): confirm if a call is live, set `ctc-phone-exit` = `'1'`, load the frame's page as the top page.

**Rules & limits.** Only one phone per browser profile.

**Browser support matrix.** Minimum versions are from memory of public compatibility data (not checked against a live source on 2026-11-11); only Chromium was live-tested.

| Browser | Web Locks + BroadcastChannel | Navigation API | Phone mode | Live-tested |
|---|---|---|---|---|
| Chrome / Edge 102+ | yes | yes | framed (NetSuite + phone in one tab) | yes (Chrome) |
| Chrome / Edge 69–101 | yes | no | phone tab | no |
| Firefox 96+ | yes | only in recent versions | framed when present, else phone tab | no |
| Safari 15.4+ | yes | only in recent versions | framed when present, else phone tab | no |
| Safari < 15.4, Firefox < 96, others without Web Locks or BroadcastChannel | no | — | no phone (banner) | no |

Known gaps outside Chromium (review R16, R17): speaker choice needs `setSinkId` (missing on Safari: the speaker list is hidden); `requireInteraction` on notifications is ignored outside Chromium; Firefox / Safari may ask for the microphone again each session.

**Key files.** `F/ctc_sl_shell.js`, `F/lib/ctc_dock.js` (constants), `src/Objects/Scripts/customscript_ctc_sl_shell.xml`.

**Open gaps.** Company Landing Page entry is parked. Not tested in the frame: Save & Print, PDF, CSV export, Change Role (the trap leaves `/app/login…` paths alone, so it probably leaves phone mode; review R4), address-editor popup windows, 2FA, SSO, Back / Forward. The 2026-11-11 in-frame fixes (unreadable banner, external links, print, form posts) are unit-tested only.

## 2. Telephony Dock (pill + dialer panel)

**Purpose.** One phone control on every NetSuite page, drawn by the shell above the NetSuite frame.

**Dock modes** (`F/lib/ctc_dock_client.js`, picked at load): `shell` draws the pill and dialer; `frame` (NetSuite page in the shell) draws nothing, routes Call to `top.__ctcShell.call(ctx)` and exposes `window.__ctcRecordContext`; `outside` (normal tab):
- **Another tab holds the phone** (Web Lock held; without Web Locks: an anchor answers the bus) → **remote control**: the same pill and 380 × 620 panel as the shell (Dial / Search / Recents, in-call controls, incoming Answer / Decline), all sending bus requests to the phone tab's anchor. The record page's Call button opens this panel on Dial (it no longer leaves the page). Its gear (settings) view shows mic and speaker (the phone tab's devices) and says "Audio plays in your phone tab." (only there); no Exit phone mode. There is no control to move the phone or its audio here (2026-11-13). The microphone and the audio stay in the phone tab. If the dialer script did not load, the tab draws the same pill words without the panel: between calls the main slot is disabled; a live call keeps End / Mute on the pill and opens the call card; the incoming card works. (The client cannot load the dialer itself: it does not know the dialer's File Cabinet media URL.)
- **A waiting shell** (lock `waiting`: another tab holds the phone) is the same remote control (2026-11-11, plan 1.10 a): full pill and panel over the other tab's anchor, no "Turn on phone" (that tab's audio), no Reload / Retry, settings with "Audio plays in your phone tab.", no Exit phone mode. It takes the phone by itself only when that tab goes away (§1). Record Call buttons in its NetSuite frame open this panel.
- **No tab holds the phone** → "Open phone" chip → shell with `u=`.
- **Phone not enabled** → nothing at all (see Errors).
Windows with `window.opener` draw nothing.

**Pill.**
- 8 snap points: rows t/m/b × columns l/c/r minus the centre (`tl tc tr ml mr bl bc br`). Default `bc`. Side margin 16 px, bottom row 24 px up. Shared across tabs in localStorage `ctc-dock-pos` (and the shared UI state below). Arrow keys walk the grid.
- Shapes: **R5** horizontal (52 px high: grip, dot, words, timer, Mute, main button) on six points; **R4** vertical (52 px wide, no words; `title` + `aria-label` carry them) on `ml` / `mr`. Ready shows no words. Muted dot is amber `#F4C76A`. Inbound on but not registered → amber dot ("reconnecting").
- **Phases:** `incoming` rings in ring blue `#6FB6D3` (dot + pulse) so ringing reads apart from a green connected call; the pill has no buttons then: horizontal reads "Ringing", vertical shows the pulsing dot only. Answer / Decline live on the incoming card (below) or in the open panel. `reconnecting` keeps the call pill (name, timer running, Mute, End) with an amber dot and amber second line "Reconnecting…". A `moved` snapshot from the anchor this tab follows (it lost the one-anchor check, §1) is drawn as **Starting** (disabled slot) until the winning anchor speaks; then the tab is the normal remote control of that anchor. An `offline` / `moved` snapshot from an anchor the tab does not follow is ignored (2026-11-13).
- **Between calls, in this order** (shell and remote tabs): error kind (below) → **Turn on phone** (shell tab only, `snap.audioUnlocked === false`, phase ready: the words read "Turn on phone"; a click calls `__ctcShell.unlockAudio()` and does not open the panel; the pill remembers the action at pointerdown / keydown, because the shell's own gesture listener can unlock and re-render first) → **missed calls** (`missedUnseen.count > 0`, phase ready: `#FF9D90` dot (the stop dot) + "N missed"; vertical: a `#FF9D90` count badge on the dot, 9+ cap). Opening the panel sends `markMissedSeen`.
- **Errors** (`snap.error.kind`, between calls only; a device error during a live call keeps the call pill): `mic` → light error pill "Microphone blocked"; `signed_out` → amber "Sign in to NetSuite" (click: Sign in = `__ctcShell.reloadFrame()` in the shell, else reload the page, so NetSuite shows its sign-in; the client label reads "Signed out", never "not receiving calls"); `session` → amber "Reconnecting…" (panel: "Reconnecting the phone…", no button); `network` → amber "Reconnecting…"; `twilio` → "Phone error". Plain phase `error` with no kind: "Phone error · Click to reconnect". `not_enabled` → no pill in any mode (the shell shows its own banner; shell lock `disabled` counts too). The dock stores localStorage `ctc-phone-not-enabled` = `'1'` and `ctc-phone-not-enabled-at` = epoch ms when a snapshot carries `not_enabled`; the flag expires after **24 h** and is cleared by any snapshot in `ready`, `incoming` or a live phase (a working token). While it is set, outside tabs draw nothing and the dashboard loader does not auto-enter phone mode.
- **Accessibility:** two visually hidden live regions in the dock's shadow root (outside `.dock`, so a hidden dock still speaks): assertive "Incoming call from X" (shell and remote tabs; the only announcement of a ring), polite "Call connected", "Reconnecting", "Call ended", "Missed call from X". Nothing is said for the first snapshot after load. The control that opens the panel carries `aria-expanded`.
- Drag: 4 px threshold; flick projection 200 ms when speed > 0.11 px/ms; no flick when the pointer was still > 100 ms before release.
- **Entrance:** one 260 ms fade + scale 0.96 → 1 (6 px travel), ease `cubic-bezier(0.23, 1, 0.32, 1)`, when the dock goes from hidden to shown. Reduced motion is honoured.
- **Readiness handshake (2026-11-11, plan 1.10 g).** A dock says `hello` at load and after an anchor change (its anchor said `moved` / `offline`; that hello has no time-out). The shell's pill shows **Starting** (disabled slot) from load until a snapshot from a working anchor with a compatible bus version (`bus` ≥ 1; a snapshot without `bus` is version 1) arrives; an incompatible snapshot is not drawn. Requests made before that wait up to **2 s** and go to the anchor that answers; after 2 s they are dropped with a quiet line "The phone is not ready yet. Try again." (the panel's muted line, 4 s, and the polite live region). `unlockAudio` never waits. A request sent to an anchor that acks (`bus` 2) and never acked when it moved or another anchor took over is reported with the same line and never sent again. In shell mode, bus silence during the first 15 s shows `starting`; after that a `hello` with no answer in 600 ms means offline (requests wait again). The dock pings every 15 s and on `visibilitychange`.
- **Double-click = one command.** The same command (action + fields) again within **1 s** goes out with the same `seq` (fresh nonce), so the anchor runs it once (one `dial` for a double-click on Call); a repeat whose first copy went to another anchor is dropped. Never for `digits` (two presses are two tones).
- **Shared UI state (2026-11-11, plan 1.10 b).** localStorage `ctc-dock-ui` = `{ v: 1, open, view: dial | search | recents | call, corner, at }`. Written when the user opens or closes the panel (pill, record Call, Answer, close, Esc), picks a Dial / Search / Recents tab or moves the dock. Applied on load (outside tabs: once the lock check says another tab holds the phone) and when the tab becomes visible or the window gets focus; never while the user works in the tab (no storage listener). `ctc-dock-pos` wins for the corner (older docks write only it). A live call always shows the in-call view; a saved `call` view with no live call keeps the current tab. Another version of the state is ignored.

**Incoming card** (`F/lib/ctc_dock_client.js`, the pill morphs into the card: sample A1, 2026-11-01).
- Shows while the phase is `incoming` and the panel is closed, in the shell and in remote tabs (phone held by another tab, with or without the dialer). Opening the panel hides it at once (the panel's ring view has Answer / Decline); closing the panel while it still rings brings it back. No card while the dock is hidden (not enabled).
- 320 px wide (at most viewport − 32), radius 16 px, navy like the pill, white text. Row: ring-blue dot `#6FB6D3` · "Incoming call" (12 px `#9FC9EE`) over the caller name, else the formatted number (15 px semibold), over "number · contact" (12 px `#94A6BF`, ellipsis, each part only when it adds something) · Decline (36 px round stop `#B3311F`, handset 135°) · Answer (36 px round go `#436B1D`). Press scale 0.97, 140 ms ease-out.
- `role="alertdialog"`, `aria-label` "Incoming call from X"; the buttons say "Answer / Decline call from X". It never takes focus by itself (a NetSuite form keeps it); Escape does nothing. `__ctcDock.focusIncoming()` focuses Answer (shell notification click). After a keyboard Answer / Decline, focus goes to the pill.
- Answer / Decline send bus `answer` / `decline` (origin `dock` + nonce) straight from the dock, in the shell too. The card then exits and stays away for that ring (call SID); the connected pill and missed counting are unchanged. Answering does not navigate.
- **Placement:** centred on the pill, kept 16 px inside the viewport: one rule for all 8 points, horizontal or vertical pill. The pill sits under the open card at opacity 0 and comes back when the card closes (at once when the dock hides). Re-placed on resize, while the pill is dragged, and on a snap (glides with the pill: `translate` 300 ms `cubic-bezier(0.32, 0.72, 0, 1)`).
- **Motion** (WAAPI, FLIP: transform + opacity only, nine-piece window, shadow on its own opacity layer; curve `cubic-bezier(0.23, 1, 0.32, 1)`): enter 1280 ms, the card scales from the pill's rect (pill radius) to its open size; the pill fades out over the first 480 ms; the card content fades in from 40 % (512 ms delay, 768 ms). Exit (answer, decline, caller hung up, phase leaves `incoming`) 880 ms: content fades out over 352 ms, the card scales back to the pill's rect, the pill fades in over the last 396 ms; a closing card takes no clicks. A new ring during an exit starts from what is drawn (interruptible). Reduced motion: opacity only, ≤150 ms. The user chose the slow pace (4× the sample) on 2026-11-01.

**Panel** (`F/lib/ctc_dock_dialer.js`).
- Fixed **380 × 620 px** for every view, capped by the screen (16 px each side, 24 px above the bottom). Views that need more scroll.
- Views: Dial (contact / number pickers, account tiles, keypad), Search, Recents, in-call (mute, end, DTMF keypad), ring (Answer / Decline), audio settings (gear: mic, speaker, Exit phone mode; in a remote control "Audio plays in your phone tab." and no Exit).
- **Call screen** (asset 38; DESIGN.md §4): one view for outbound and for inbound once answered. Identity (person icon, name, contact · title, number without +1) over a fixed slot ("Calling…" / timer / "Reconnecting…" / "Call ended · m:ss"); the account block from `softphoneCallContext` (fetched through the dialer's 60 s record cache, prefetched on record load and on dial): KPI grid (Outstanding · Last touch · 90-day orders), Recent activity, Follow-ups; 65px round controls (Mute / End / Keypad; in-call keypad = the Dial keys). Wrap-up stays on the call screen for 8 s ("Summary · Summarizing…", Call back, Done → Dial with the record); it no longer jumps to Search. Unknown caller: the number as the name, "Not in NetSuite" + Add to NetSuite, no account block. The ring view and the incoming card are unchanged (asset 39).
- **Recents** (RESTlet `softphoneRecents` → `loadHistoryRows({ dateRange: 'last7days' })` = `startdate onorafter daysago7`; `last30days` = `daysago30`. The old `within lastweektodate` meant last week up to the same weekday and returned nothing for this week's calls). Scope: calls to the rep's book, plus the rep's own calls with no company (an unknown number: `assigned` = the rep AND company empty), in one search (`includeUnlinked`). Each row carries `unknown`: true when it has no company and no contact (the number in `phone`), else false. Worst case 40 units, the same as before. `softphoneVoicemails` keeps the book scope only. Each row: direction icon (20 px circle, 12 px arrow: down-left for in / missed, up-right for out; panel tints of the portlet colours — In `rgba(111,182,211,0.18)` / `#9FD0FA`, Out `rgba(255,255,255,0.10)` / `#C9D3E1`, Missed `rgba(255,157,144,0.20)` / `#FFA595`, arrow vs circle ≥ 5:1; `role="img"` + aria-label + title "Inbound call" / "Outbound call" / "Missed call"), name, sub line, date + minutes. ## 3. Softphone (anchor)

**Purpose.** Holds the Twilio Device, call state, bus host and call logging.

**Token.** RESTlet `customscript_ctc_rl_token` (POST, no `action`) builds a Twilio Access Token with N/crypto HMAC-SHA256 (`F/lib/ctc_twilio_jwt.js`): ttl 3600 s, `cty: twilio-fpa;v=1`, identity = NetSuite employee internal id, `outgoing.application_sid` = `custrecord_ctc_twiml_app_sid`, `incoming.allow` = `custrecord_ctc_inbound_enabled`. Signing secret: NetSuite API Secret named by `custrecord_ctc_api_secret_id`.

**Phone user gate** (`isPhoneUser` in `F/ctc_rl_token.js`). A token is issued only when `custrecord_ctc_active` is true AND one of: the session user has an active `customrecord_ctc_rep_assignment` (`custrecord_ctc_ra_employee`, `isinactive` F); the session user is the `supervisor` of an employee with one (search join `custrecord_ctc_ra_employee.supervisor`); the session role is Administrator (3). Else `{ error: 'not_a_phone_user' }` (audit `CTC RESTlet — not a phone user` with the reason); when the reason is `ctc_inactive` (paused) the answer adds `paused: true`, so the phone pauses instead of disabling itself. The same gate runs before every phone action: `logCall`, `checkTranscript`, `lookupCaller`, `phoneHeartbeat`, `softphoneSuggested`, `softphoneSearch`, `softphoneContacts`, `softphoneRecents`, `softphoneAccountSnapshot`, `softphoneCallContext`, `softphoneBookCounts`, `softphoneFindDuplicates`, `softphoneAddToNetSuite`. Open to every internal user (portlet / Reporting Central): `getWorkspaceHistory`, `getCallDetail` (Reporting Central's own scope check, §9), the proposed-task actions (own checks). Decided once per request, never cached across requests. Fails closed: a config or search error denies. Cost: config search + up to 2 assignment searches (≈ 30 units).

**Timing flag.** Every RESTlet request logs `CTC perf` (debug, `<action> <ms>ms`); with `perf: true` in the body an object answer also gains `_perf: { ms, units, steps }` (whole request incl. gate, governance units used, ms per named step of `lookupCaller` / `softphoneContacts` / `softphoneAccountSnapshot` / `softphoneCallContext`), and without it the answer is unchanged.

**Contact list** (`softphoneContacts`, phone action). Answers `{ rows, lastCalled }`: `lastCalled` is the session user's most recent Phone Call to `entityId` in the last 90 days with a number (`assigned` = user, `company` = entityId, `phone` not empty, newest first; `lastCallForRecord` in `F/lib/ctc_workspace_queries.js`) as `{ contactId ('' with no contact), number (Phone Call `phone`), at (`custevent_ctc_call_started`, ISO UTC) }`, else null (also when that search fails; the rows still return). +10 units.

**Call screen context** (`softphoneCallContext`, phone action; `getCallContext` in `F/lib/ctc_workspace_queries.js`; DESIGN.md §4 "Account context on the call screen"). Body `{ entityId, contactId? }`. Answers `{ outstanding: { sum, count, overdueCount, oldestDays }, lastTouchDays, orders90: { count, total }, activity: [{ kind, text, at, ageDays }], followUps: [{ id, title, due }] }`. Sources, each in its own try/catch (a failure logs `CTC getCallContext <source> failed` and leaves that part empty): `outstanding` (open / partially paid invoices; overdue = `duedate` before today; oldest by `trandate`), `orders` (Sales Orders, mainline, `trandate` in the last 90 days: count, sum of `amount`, newest 2 as "Order SO-1 · $8,200 · Billed"), `calls` (Phone Calls with `company` = entity, newest 3: "Call with <contact first name or company> · <title>"), `emails` (Messages filtered on `entity`, newest 2: "Email · <subject>"; filter not yet proven live), `tasks` / `events` (newest one each, last touch only), `followUps` (Pending proposed tasks whose call's `company` is the entity, earliest due first, no due last, 3). `activity` = calls + emails + orders, newest first, 4; `at` is 'YYYY-MM-DD'; `lastTouchDays` = days since the newest item of any source. With `perf: true` the answer adds `errors` (names of the failed sources). 7 searches = 70 units + the gate. Nothing is cached.

**Add to NetSuite actions** (unknown numbers, DESIGN.md §6; `F/lib/ctc_add_to_netsuite.js`; built 2026-11-13, not live-tested). Both are phone actions (gate above). The RESTlet passes only the listed body fields to the lib. Failure is `{ ok: false, error, message }` with error `invalid`, `no_permission`, `not_found`, `not_owner`, `duplicate`, `no_empty_field` or `failed`.
- `softphoneFindDuplicates` (`phone`, `companyName`; one or both): records that already hold the number (`byPhone`) and companies with that name (`byName`). At most 10 rows each. ≤ 30 units.
- `softphoneAddToNetSuite` with `mode`: `existingContact` (`contactId`, `phone`, `field`, `makeMain`) adds the number to a contact; `newContact` (`companyId`, `firstName`, `lastName`, `title`, `phone`, `makeMain`) creates a contact at a company; `newCompany` (`companyName`, `firstName`, `lastName`, `phone`, `status` `lead` | `prospect`, default `lead`) creates a Lead or Prospect, and a contact when a name is given; `logOnly` (`phoneCallId`, required) writes nothing. Another mode → `invalid`.
- With `phoneCallId`, a successful write then links that Phone Call to the result's company and contact (only the rep's own call). The answer is the lib result plus `linked` (true / false) and, when the link fails, `linkError` (the error code). A failed link does not undo the write: `ok` stays true. A failed write returns the lib failure and does not link. ≤ 46 units.

**Renewal.** Device option `tokenRefreshMs` 60 000 → `tokenWillExpire` → fetch token → `device.updateToken()`. Expiry codes 20101, 20104, 31204, 31205, 31206 renew and re-register instead of showing Error (20101 = invalid token, e.g. its API key was deleted after a key change). The first refusal fetches a token at once; another refusal within 5 min waits 5 s, 15 s, 30 s, then 60 s (`renewExpiredToken`), one renewal at a time. Every token answer sets the caller ID (`phoneNumber`), so a per-rep caller ID change reaches an open phone at its next renewal. Audio setup runs only on the first registration. A renewal never resets a live call.

**Token recovery (session gone).** A token fetch fails on a non-OK status (`HTTP 401`), a non-JSON answer such as the login page (`not JSON (redirected)`), a JSON error (`error: …`), no token, or a network error. The phone never gives up while the page is open (except `not_a_phone_user`, below): retries after 5 s, 15 s, 30 s, then every 60 s (`TOKEN_RETRY_DELAYS_MS`), and at once on page visible, `online` and `focus` while a retry waits. One fetch at a time; register() waits meanwhile. While fetches fail the snapshot has `canReceive: false` (amber "reconnecting" hint) and the error goes to the heartbeat `lastError`. The first token after a failure **rebuilds the device** (`rebuildDevice`: fresh session and identity) when no call is live; during a call the token is applied now and the rebuild runs when the call settles. A failed first fetch at page load shows "Failed to initialize" and keeps retrying; the device starts when a token comes. There is no "Phone session expired" give-up any more.

**Device.** `codecPreferences ['opus', 'pcmu']`, `allowIncomingWhileBusy: false`, `edge ['ashburn', 'umatilla']` (signaling fallback), `maxCallSignalingTimeoutMs 30000` (a call keeps reconnecting its signaling for up to 30 s; needs the edge list), `logLevel` 3 (warn), 1 with `debug=1`. SDK 2.7.3 bundled at `F/lib/twilio.min.js` (CDN blocked by CSP); both option names are in that build. Only a token with the incoming grant registers; an outbound-only phone is Ready at once (`deviceReady`) and never calls `register()`.

**Call resilience.** Call `reconnecting` → phase `reconnecting` (call, timer and mute kept); `reconnected` → `connected`. Call `warning` / `warning-cleared` → `callWarning` (most severe active one; cleared on `reconnected` and at call end). A device `error` during a live or ringing call sets the snapshot `error` and logs a warning but never resets the call view; with no call it shows Error as before.

**Errors (snapshot `error`).** From the Twilio code: 20101 / 20104 / 31204–31206 → `session`; 31208 / 31401 → `mic`; other 31xxx → `network`; else `twilio`. Token fetch failures → `signed_out` when NetSuite answered 401 / 403 or its login page (not JSON), else `session` (offline, server error; code = HTTP status). **Session watch:** every 60 s, and at once when the page comes back online or visible, the softphone POSTs RESTlet action `sessionPing` (no gate; one config search; answers `{ok: true, active}` with `active` = `custrecord_ctc_active`, `false` when there is no config record, left out on another config read error; NetSuite answers 401 SESSION_TIMED_OUT before the script when the session is gone). A 401 / 403 / login page starts the token recovery loop at once (→ `signed_out`); offline or other failures do nothing. Before this a lost session showed only at the hourly token renewal. A network change ends the NetSuite session (soak test 2026-11-02). Register time-out → `network`. Mic permission (`navigator.permissions.query({name:'microphone'})`, watched with `onchange`) `denied`, or `getUserMedia` NotAllowedError → `mic`. Cleared by kind on recovery: token back (session, signed_out), `registered` (network, twilio), call accepted (network, twilio, mic), permission back (mic).

**Pause.** `sessionPing` `active: false` (or a token answer with `paused: true`) pauses the phone within about a minute: no token fetches, no registration (unregister now, or right after a live / ringing call ends; the call is never ended), `dial` refused (`paused`), status "Calling paused", error `{kind: 'paused', code: 'ctc_paused', message: 'Calling is paused by your administrator'}`, snapshot `canReceive: null`. `sessionPing` keeps running; `active: true` clears the error, shows Ready and fetches a fresh token, which registers the phone again (no reload). An answer without `active` changes nothing. Heartbeats, `logCall` and lookups are refused while paused (§3 gate); calls that end after the pause are logged later by reconciliation (§7).

**Not a phone user.** A token answer `{error: 'not_a_phone_user'}` (without `paused`) is permanent: no token retries, no registration, phase `error`, error `{kind: 'not_enabled', code: 'not_a_phone_user', message: 'Phone is not enabled for your user'}`, and `ctc-phone-disabled` to the shell (§1). A live call is left to end by itself.

**Missed calls.** An inbound call cancelled before Answer (caller hung up or ring timeout; not Decline) adds to `missedUnseen` (count, last caller, time). Bus `markMissedSeen` resets it. Kept in sessionStorage `ctc-missed-unseen` (shared by the shell tab and its phone frame), so a phone-frame restart keeps it; another tab starts at 0.

**Page Lifecycle.** `freeze` → a `phoneHeartbeat` beacon with state `frozen`; `resume` → re-register, renew the token when it ends within 90 s (or already ended), heartbeat. The after-call `logCall` beacon is sent on `pagehide` (was `beforeunload`).

**Registration watchdog** (only while the token grants incoming, and never after the anchor stepped aside (one anchor, §1) or `not_a_phone_user`). On `unregistered`: retry after 2 s, 5 s, 15 s, 30 s, then every 60 s, one timer at a time. Try now on page visible, `online`, `focus`, page `resume`. Every 60 s when no retry is pending. Never during a live or ringing call or an in-flight token refresh. Each `register()` races a **20 s** timeout: a time-out frees the slot, sets error `network` and schedules a retry; if that retry finds the device still `registering` (the SDK refuses a second `register()`), the device is rebuilt with a fresh token. Every `register()` goes through this path (with its catch).

**Identity rebuild.** When a renewed token carries a different identity (NetSuite user changed), the device is rebuilt; during a live or ringing call the rebuild waits until the call settles. A changed incoming grant is applied to the existing device (`applyIncomingGrant`), which re-registers it.

**Heartbeat.** RESTlet action `phoneHeartbeat` on every registration change, after a token refresh, on the first token failure, every 5 min, and an `offline` beacon on `pagehide`. Coalesced: at most one per 2 s (`HEARTBEAT_MIN_GAP_MS`); a burst sends once now and once at the end of the gap with the latest state. Body adds `identity` (the token's identity, for comparison only) and `lastError` (e.g. `token: HTTP 401 at 01:02Z`, `register: 31204 at 01:02Z`, ≤ 200 chars). `lastError` is queued and sent with every heartbeat until one succeeds (OK status and a JSON answer without `error`); a newer error replaces it. See §8.

**Key files.** `F/ctc_sl_softphone.js`, `F/ctc_rl_token.js`, `F/lib/ctc_twilio_jwt.js`.

**Open gaps.** A change of identity or grant is caught only at the next token renewal (up to 1 h; the wizard says "within an hour, or at once after a reload"). The RESTlet `phoneHeartbeat` accepts `registered | unregistered | registering | offline | frozen` (`PRESENCE_STATES` in `F/ctc_rl_token.js`). Live checks pending: `edge` / `maxCallSignalingTimeoutMs` reconnect (network off/on mid-call), warning names, the audio unlock on a cold tab, the freeze / resume path.

## 4. Outbound calling & logging

**Current behaviour.**
- Call from a record (phone icon / Call button, VIEW and EDIT mode) or from the dialer. The anchor runs `device.connect({ params: { To, CallerId } })`; caller ID = `phoneNumber` from the token response. **Caller ID rule** (`F/ctc_rl_token.js` `resolveCallerId`): the number whose inbound calls ring the session rep (inbound routing's rule, `F/lib/ctc_inbound_routing.js` `loadRoutes`: a number's primary rep, else its first assigned rep; one search per token), so a callback reaches the same rep; a rep who rings for no number (e.g. a secondary on a shared number) uses the config default caller ID `custrecord_ctc_phone_number`. The rep comes from the session, never the request. A failed lookup is logged (`CTC caller ID lookup failed — using the default caller ID`) and falls back; it never fails the token. The outbound Function uses `CallerId`, else `CALLER_ID_DEFAULT`.
- The TwiML App points at the outbound **Twilio Function** `https://{ctc-outbound domain}/dial` once the wizard has published it (§4a); before that, at a hand-made **TwiML Bin** that does `<Dial record="record-from-answer-dual">`. Both record the parent (browser) leg dual-channel.
- `logCall` (outbound only) also writes `custevent_ctc_notice_played` and, when played, `custevent_ctc_notice_ver` (§4a). No extra Twilio call.
- At hang-up the browser posts RESTlet `logCall` (`sendBeacon` on unload) with `startedAt` (epoch ms the call connected). The RESTlet creates a Phone Call (`record.Type.PHONE_CALL`) with `custevent_ctc_call_sid`, duration, entity / contact, status `Logged`, `custevent_ctc_inbound` for inbound, and `custevent_ctc_call_started` (ISO-8601 UTC): Twilio's `start_time` from the ownership check, else `startedAt` when within ±1 day of now, else now − duration. `starttime` / Reserve Time are not set.
- **Ownership check** (`F/lib/ctc_call_ownership.js`, `verifyCallOwnership`): the RESTlet fetches the Twilio call (`F/lib/ctc_twilio_admin.js` `getCall`: `sid`, `from`, `to`, `callStatus`, `duration`, `start_time`, `parent_call_sid`). Outbound: `from` must be `client:<rep id>`; or, when `from` is a phone number (a dialed child leg), its `parent_call_sid` is fetched and the parent's `from` must be `client:<rep id>`. A caller ID alone (assigned number or the config caller ID) is not accepted. Inbound: the leg's `to` must be `client:<rep id>`. Failure → `forbidden` (`NOT_CALL_OWNER`, `CALL_NOT_FOUND`, `TWILIO_LOOKUP_FAILED`).
- Duplicate `callSid` returns the existing record (`duplicate: true`).
- After logging, the browser polls `checkTranscript` every 15 s, up to 12 attempts.
- **`checkTranscript` is idempotent** (after the binding and ownership checks): a stored terminal status (Transcribed, No transcript, Missed, Too short, No answer) or `custevent_ctc_processed` T returns at once with no Twilio work and no write — Transcribed → `{status:'completed', alreadyDone:true}`; claimed (processed T + Processing) → `{status:'pending', reason:'claimed'}`; others → `{status:'terminal', reason:'already_closed'}`. Before the LLM it **claims** the call (§6).

**Rules & limits.**
- Browser: calls with no connect (duration 0) are not logged; calls under **3 s** are skipped ("Call too brief to log"). RESTlet: rejects under **2 s** (`duration_below_threshold`; Twilio does not transcribe recordings under 2 s).
- Phone must match `^\+?[0-9]{7,15}$`.
- **Orphan queue:** a transient `save()` failure (`RCRD_HAS_BEEN_CHANGED`, `SSS_REQUEST_LIMIT_EXCEEDED`, `CONCURRENT_REQUEST_LIMIT_EXCEEDED`, `UNEXPECTED_ERROR`; `SSS_RECORD_TYPE_REQ_FIELD_MISSING` is not transient → `NON_TRANSIENT_SAVE`) writes `customrecord_ctc_orphan_call`. Poller Phase B retries up to 50 rows with `custrecord_ctc_orphan_retrycount` < 3, re-checking ownership first.

**Key files.** `F/ctc_ue_phone_button.js`, `F/ctc_sl_softphone.js`, `F/ctc_rl_token.js`, `F/lib/ctc_call_ownership.js`.

**Open gaps.** README / ARCHITECTURE show the Bin with `callerId="{{From}}"`; the browser sends `CallerId`, so the Bin text in the docs may be stale. The outbound recording notice (§4a) is built, not live-tested end to end through NetSuite.

## 4a. Outbound recording notice (Twilio Function, built 2026-11-03, not live-tested)

**Behaviour.** With the notice on, the person a rep calls hears a short notice after they answer and before the legs bridge; the rep hears ringing (`answerOnBridge`). The recording starts after the notice, so the notice is not in the recording (spike 2026-11-03). Recording stays on the parent (rep browser) leg, dual-channel: the transcript lookup, speaker channels and ownership check are unchanged. (max 300 characters; the Function speaks the whole word "AI" as "A I").

## 5. Inbound calling

**Purpose.** A customer calls a rep's Twilio number; the rep's pill rings; the call is answered in the browser and logged.

**Routing flow.** `F/lib/ctc_inbound_routing.js` builds **one Studio flow for all numbers**, friendly name `CTC Inbound Routing`, from rep assignments:
- `routesFromAssignments`: one route per phone SID — the **primary rep** (`custrecord_ctc_ra_is_primary`), else the first assigned employee. Inactive assignment rows, rows without an employee and numbers without digits are skipped. A second SID with the same E.164 number is skipped. At most 50 routes.
- Shape: `Trigger ─incomingCall─▶ [recording_notice] ─▶ split_dialed ─To == route n─▶ ring_n` (connect-call-to `client:<employeeId>`, `caller_id {{contact.channel.address}}`, `timeout` = ring seconds, `record` = record flag) `─callCompleted─▶ answered_n` (`DialCallStatus == completed` → end, else → `no_answer`). `split_dialed` noMatch → `no_answer` (say-play message). The `answered_n` split is required: callCompleted fires for answered calls too.
- **Voicemail** (`custrecord_ctc_voicemail_on`, default on): `no_answer ─audioComplete─▶ voicemail` (Studio `record-voicemail`: `timeout` 5 s silence, `max_length` = `custrecord_ctc_voicemail_max_seconds` (default 120, clamped 30–300), `finish_on_key '#'`, `play_beep 'true'`, `trim 'trim-silence'`, `transcribe false`) `─recordingComplete / noAudio─▶ voicemail_goodbye` (say-play "Thank you for your message. Goodbye.") → end; `hangup` → end (Twilio keeps the recording). Unanswered rings, unrouted numbers (`split_dialed` noMatch) and a flow with no routes all reach it through `no_answer`. Voicemail off → `no_answer` then hang-up (as before). Legacy `<Record>` transcription stays off: Conversational Intelligence transcribes the voicemail (§6).
- **Publish** (`publishRouting`): skipped when inbound is off (no Twilio call; the numbers keep pointing at the flow). Order (2026-11-03): create/update the flow (`upsertStudioFlow`) → store `custrecord_ctc_studio_flow_sid` when it changed (if that save fails, stop before any number: "Publish again") → point each routed number's VoiceUrl at the flow (`setNumberVoiceUrl`), keeping 100 units in reserve per number → only when every number was pointed, store `custrecord_ctc_routing_published_at`. Result: `{ok:true, flowSid, publishedAt, numbersUpdated, errors:[]}`; partial = `{ok:false, partial:true, message:'Routing is only partly published: N numbers were not updated. Publish again.', flowSid, publishedAt: <previous time>, numbersUpdated, errors:[{phoneNumber, message}], failedNumbers:[e164]}`; failed = `{ok:false, message, …}` with the previous time. A partial publish therefore never looks complete. Every attempt (not inbound off) also stores the routing state (below). The SPA shows the outcome until reload: Inbound page status line + the message + one line per failed number; Phones & reps "⚠ Inbound routing did not update for: …" or "⚠ Inbound routing did not publish: <message>". Triggered by wizard "Save & publish" / "Publish again" (`wizardSaveInbound`, `wizardPublishRouting`) and automatically after `wizardSaveAssignments` when inbound is on.

**Routing state** (`custrecord_ctc_routing_state`, CLOBTEXT JSON, Phase 1 2026-11-03). Written at the end of every publish attempt by `publishRouting` (`buildRoutingState` + `F/lib/ctc_config.js` `writeRoutingState`; one `submitFields`, 2 units; a failed write never changes the publish result):

`{ v: 1, builderVersion, flowHash, routesHash, routes: [{ phoneSid, employeeId }], flowSid, revision, result: 'ok' | 'partial' | 'failed', message, failedNumbers: [e164], at, publishedAt }`.

- `routesHash` = cyrb53 (`F/lib/ctc_hash.js`) of the routes `[[phoneSid, e164, employeeId], …]` in order: "who rings which number". `flowHash` = cyrb53 of `FLOW_BUILDER_VERSION` (now `'1'`) + the flow definition (ring time, messages, recording, notice, voicemail; no time stamp) + the routed phone SIDs, sorted. Both from `routingHashes(routes, cfg)`.
- `ok` / `partial`: the new hashes, routes, flow SID and revision (the flow is live). `partial` keeps the previous `publishedAt` and lists `failedNumbers`. `failed` keeps the previous hashes, routes, flow SID and revision (they still describe what is live) and sets `result`, `message`, `at`. If the publish time cannot be saved but every number was pointed, the state says `ok`.
- Read with `readRoutingState` (`record.load`, 2 units; `{ok, state}` or `{ok:false}` on an unreadable field or bad JSON). Before the first publish after this change the field is blank (`state: null`).

**Ring & answer.** The dock shows the incoming card at the pill (§2) and, when the tab is away, the shell adds a system notification and a flashing title (§1). Ring time `custrecord_ctc_ring_seconds`: default 20, clamped 10–60. No-answer message `custrecord_ctc_noanswer_message`. Blank, or text equal to a built-in default, gives the default for the voicemail setting: voicemail on → "Sorry, no one is available. Please leave a message after the tone."; off → "Sorry, no one is available to take your call. Please try again later. Goodbye." The wizard stores a built-in default as blank, so the text follows the switch. The anchor holds one pending call; a second call while busy is rejected. Caller cancel / ring timeout → `missed` note and `missedUnseen` + 1 (§3); Decline → `skipped` note.

**Caller match.** RESTlet `lookupCaller` → `lookupCallerByPhone`: last 10 digits (non-digits stripped both sides, SuiteQL `REGEXP_REPLACE`), customer / prospect / lead / contact; a match in the rep's book wins; a contact with a company returns the company as entity. The name fills in by a second snapshot. After Answer the page stays where it is; the panel shows the match with Open record. The lookup is book first: the customer and contact matches run first limited to the rep's book (`c.id IN (…)` / `ct.company IN (…)`, 200 ids per query) and return at once on a hit (`inBook` true); only a book miss runs the scans over all customers and contacts (2 SuiteQL on a book customer hit, 3 on a book contact hit, 5 on a miss).

**Logging.** Answered inbound ≥ 3 s → `logCall` with `direction: 'inbound'` → `custevent_ctc_inbound` T. Missed inbound calls and voicemails are logged only by reconciliation (§7).

**Fallback owner** `custrecord_ctc_fallback_owner` (employee, wizard "Unrouted calls and voicemails go to"): owns reconciled calls and voicemails for numbers with no route, and for calls whose rep is inactive or unknown. Not set → those calls are not logged.

**Recording.** `custrecord_ctc_record_inbound` → `record: true` on every ring widget. `custrecord_ctc_recording_notice_on` (applies only with recording on) adds one say-play before the split; text `custrecord_ctc_recording_notice` (blank → "This call may be recorded for quality and training.").

## 6. Recording, transcription & AI analysis

**Recording.** Outbound: `record-from-answer-dual` from the outbound Function `/dial` (§4a) or the older TwiML Bin. Inbound: Studio `record: true`; Twilio attaches the recording to the **parent** call (caller leg). The poller and RESTlet find it through the child leg's `parent_call_sid`.

**Transcription.** Twilio Conversational Intelligence service `custrecord_ctc_intel_service_sid` transcribes the recording. No code creates transcripts: the service must have auto-transcribe on (README setup step), which covers every recording in the account, voicemails included. The poller reads `intelligence.twilio.com/v2/Transcripts?SourceSid=<recording>` and `/Sentences`. Speaker labels: dual-channel channel 1 = parent leg; outbound rep = channel 1, inbound rep = channel 2.

**Poller** `customscript_ctc_ss_poll` (`F/ctc_ss_poll_transcripts.js`), five deployments picked by the script parameter `custscript_ctc_poll_mode` (TEXT, not mandatory):
- `customdeploy_ctc_ss_poll`, mode `transcripts` (also when empty): daily, every 1 day, from 06:00Z, repeat PT15M. Phases A cleanup-pending recording deletes (≤ 50); B orphan retry (≤ 50); C0 stale analysis claims (≤ 20, below); C unprocessed Phone Calls (≤ 50, **oldest first**: internal id ascending). Yields with `task.create` (this deployment) when fewer than 1000 units remain. Audit `CTC Poll Complete`: `main(processed, skipped, noTranscript, transient, alreadyDone, errors, transientExpired, gaveUp[, crashed=true]) cleanup(…) orphan(…) stale(released, gaveUp)`. A crash outside the per-call catch (config, auth, a search) counts in `errors` and adds `crashed=true` (before: `errors=0`).
- `customdeploy_ctc_ss_poll_recon`, mode `reconcile`: daily, from 06:00Z (SDF allows only 30-minute start increments), repeat PT15M. Phase D reconciliation only (§7), with the whole run's budget. Audit `CTC Poll Complete`: `recon(seen, existing, created(missed, tooShort, noAnswer, logged, voicemail), deferred, skipped, errors, complete[, stopped][, dropped])`.
- `customdeploy_ctc_ss_poll_tick00` / `_tick12` / `_tick18`, mode `tick`: daily from 00:00Z / 12:00Z / 18:00Z, repeat PT15M. No work: each run queues the two deployments above (`task.create`, 40 units; "already queued or running" is expected and logs at debug).
- Any other mode: error `CTC Poll — unknown mode`, nothing done.

**Schedule and time zone** (2026-11-03). SDF `starttime` is UTC; NetSuite converts it to the account time zone, and a daily repeat runs only from that local start to the end of the local day. One fixed start is local midnight in one offset only (06:00Z = 12:00 am in UTC−6; Pacific got about 2 h of runs a day). SDF has no recurrence that repeats across midnight, scripts cannot edit a deployment schedule (`scriptdeployment` is read and search only), and N/task cannot delay a run. So the five deployments start every 6 h (00, 06, 12, 18 UTC): in every time zone one start falls between 12:00 am and 6:00 am local, and from there to midnight a run is due every 15 min. NetSuite never runs one deployment twice at once, so ticks cannot make a mode run in parallel; at most they queue one extra run. Worst-case gap: under 6 h, overnight (local midnight to the first start; 5.5 h for UTC+5:30). A gap only delays work: the transcript waits use Twilio times and reconciliation reads from its watermark. Not live-tested: check Scheduled Script Status after deploy (each deployment's Start Time, and that tick runs queue the two working deployments).

**Claim before the LLM** (`F/lib/ctc_call_claim.js`). The browser (`checkTranscript`) and Phase C both claim a call before the LLM: a fresh read (`lookupFields`), then, only when not terminal and not processed, write `Processing` + `custevent_ctc_processed` T + `custevent_ctc_analysis_claim` = `<ISO-8601 UTC claim time>|<claim count>` (the count goes on from the stored stamp). processed T takes the call out of Phase C's search; the enrichment save then writes Transcribed. Already finished or claimed → no LLM (Phase C counts `alreadyDone`; the RESTlet answers as above). A failed claim write is transient (retry). An error after the claim releases it: `Failed` + processed F (Phase C retries). **Attempt cap** (2026-11-03): each claim is one attempt (one LLM call); a call whose stamp count already reached `MAX_ANALYSIS_ATTEMPTS` (3, same as the stale-release cap) is not claimed again: the claim writes `Failed` + processed T, empties the stamp, logs `CTC analysis gave up — attempt cap` (count in the log), and Phase C counts `gaveUp` (the RESTlet answers terminal). Before, a `Failed` call was retried every 15 min forever, one LLM call each time. NetSuite has no compare-and-swap: the race window is the gap between the fresh read and the write. The enrichment save (both paths) empties the stamp.

**Stale claims** (Phase C0, before C). A script killed between claim and save leaves processed T + Processing. The poller searches calls with the stamp set, processed T and no `custevent_ctc_ai_summary` (≤ 20). Status Processing and stamp older than **30 min** (or unreadable) → back to `Logged` + processed F, stamp kept, and Phase C retries it in the same run. When the stamp count is over **3** (3 retries used) → `Failed` + processed T and the stamp emptied: never retried again (the Twilio recording is not deleted). Own try/catch; a failed release is logged and skipped. The time is the stamp's UTC time, not `lastmodified` (search dates come back in the user's format and time zone).

**Statuses** (`custevent_ctc_call_status`, `CALL_STATUS` in `F/lib/ctc_transcript_utils.js`): `Logged`, `Processing`, `Transcribed`, `No transcript`, `Failed`, `Missed`, `Too short`, `No answer`. Terminal: Transcribed, No transcript, Missed, Too short, No answer. A terminal status also sets `custevent_ctc_processed` T. `Processing` is written once while waiting (processed F); `Processing` with processed T is an analysis claim.

**Wait rules.** No recording: read the Twilio Call; 1 h after the call ended (or at once if Twilio has no such call) → `No transcript`. Recording but no finished transcript: 24 h after the recording last changed → `No transcript`. Recording status `absent` or `deleted` is terminal. Times use Twilio UTC timestamps. Network errors, timeouts, 5xx, 401, 403 and 429 are transient: retry next cycle without a status write, but **bounded** (2026-11-03, `transientWaitExpired`): when the recording is known (transcript or sentences read failed), 24 h after the recording last changed; when it is not (recording or call read failed), 25 h (1 h + 24 h) after `custevent_ctc_call_started`, so an admin has a day to fix rotated credentials. Past the wait → `No transcript` + processed T, audit `CTC Transient wait expired — closed as No transcript`, counter `transientExpired`; the recording stays in Twilio. No readable start time → keeps waiting.

**Sentences** (2026-11-03). `fetchSentences` reads EVERY page (`PageSize=1000`, follows `meta.next_page_url` on `intelligence.twilio.com/v2` only, at most 20 pages = 10 units each) and returns all sentences in order; any page that fails, a next page off that host, or the page cap → `TRANSIENT_ERROR` (never a partial transcript). Before, only the first page (Twilio's default 50 sentences) was read, so long calls lost the end of the transcript. It returns the sentences of 200 answers, else `TRANSIENT_ERROR` (network, 5xx, any 4xx incl. 404, bad JSON, no `sentences` list). Both callers read the sentences BEFORE the claim: on failure nothing is saved, the recording is not deleted and no attempt is spent (Phase C: transient, bounded as above; RESTlet: `{status:'transient', reason:'twilio_unreachable'}`). Before, every failure returned `[]` and the call was saved `Transcribed` with an empty transcript and its recording deleted (data loss). A real empty transcript (200 with `sentences: []`) is saved as before.

**AI analysis** (`F/lib/ctc_llm_analysis.js`). N/llm `modelFamily: 'cohere.command-a-03-2025'`, temperature 0.2, maxTokens 800. Writes `custevent_ctc_ai_summary`, `custevent_ctc_ai_brief`, `custevent_ctc_satisfaction`, `custevent_ctc_tone_keywords`, `custevent_ctc_action_items`, `custevent_ctc_transcript`, and proposed tasks (`customrecord_ctc_proposed_task`). Proposed tasks are created only AFTER the Phone Call save succeeds, by `createProposedTasksOnce` (both callers): skipped when any proposed task already points at the call (one search, 10 units); never throws. Before (until 2026-11-03) they were created inside `writePhoneCallEnrichmentFields` before `save()`, so a failed save or a killed script duplicated them on every retry. A script killed between the save and the tasks leaves the call with no tasks (not retried). Skipped for the cycle when free usage < 10. JSON fences are stripped before parsing.
- **Date reference line.** `analyzeTranscript(text, opts, context)`; `context` = `{ today, callDate, timezone, phoneCallId }` from `ctcTime.analysisDates(custevent_ctc_call_started)` (`F/lib/ctc_time.js`: user time zone via `userTimezone` + `localParts`, date part back through `format.parse`; call date = today when the start is blank; server clock when N/format gives no date). Both callers pass it: RESTlet `checkTranscript` (from the loaded Phone Call) and poller Phase C (the search reads `custevent_ctc_call_started`). The prompt starts with "Today is <Weekday, YYYY-MM-DD> (<time zone>). The call took place on <Weekday, YYYY-MM-DD>." (time zone part left out when unknown; no context → server-clock today).
- **Action items** are objects `{"task": string, "due_date": "YYYY-MM-DD" | null}`. The prompt says: resolve relative timing ("next Tuesday", "end of week", "in two weeks") against the call date; `null` when the call gives no timing. Plain strings are still accepted (`normalizeActionItems`, `F/lib/ctc_transcript_utils.js`); other shapes and empty tasks are dropped. `custevent_ctc_action_items` stores the task texts, one per line.
- **Proposed task due date** (`createProposedTasksFromAnalysis(phoneCallId, analysis, callDate)`): the AI `due_date` when it is a real `YYYY-MM-DD` date from the call date through call date + 90 days; anything else → call date + 3 business days (Saturday / Sunday skipped).
- **Fallback title** (no AI title and no summary): "Voicemail from <who>" / "Inbound call from <who>" / "Call to <who>"; <who> = company, else contact, else the phone number, else "unknown". Never the recording SID. ("Voicemail: " prefix only on AI titles.)
- **Quota read** (`remainingUsage` in `F/lib/ctc_llm_analysis.js`, 2026-11-03): `llm.getRemainingUsage()` when the function exists and gives a number (NetSuite 2026.2 deprecates the old one), else `llm.getRemainingFreeUsage()`. `hasQuota` = remaining ≥ 10 (`QUOTA_RESERVE_THRESHOLD`). Oracle publishes no pool size, so the console shows the remaining number only.
- **Failures are logged with `log.error`** and the Phone Call id (`phoneCall=<id> reason=…`): quota below the reserve ("CTC LLM quota below reserve", and "CTC LLM analysis skipped" in both callers), the N/llm error name + message ("CTC LLM call failed"), JSON parse failure or a non-object JSON ("CTC LLM JSON Parse Failed", with the first 500 chars).

**Voicemail transcripts.** One transcript path, no new status. ## 7. Call reconciliation (poller Phase D)

**Purpose.** Only the browser logs calls. Calls < 3 s, missed inbound calls and calls cut off by a crash or reload leave no Phone Call. Twilio is the source of truth.

**Current behaviour** (`F/lib/ctc_call_reconcile.js`, built, not yet committed).
- Lists Twilio Calls (page size 100) that ended since the watermark. Keeps only browser legs: inbound = `to` `client:<id>`; outbound = `from` `client:<id>`. Terminal statuses only: completed, busy, no-answer, canceled, failed.
- A call is created only when its end time is **5 min** old.
- **Dedupe:** already logged when a Phone Call has its own SID, or (inbound) its parent SID, or (outbound) one of its child SIDs (child page size 20). Batch SuiteQL check per page (chunks of 200), a second check right before create, one handling per SID per run.
- **Status mapping:** not answered (status ≠ completed or 0 s) → inbound `Missed` ("Missed call from <name or number>"), outbound `No answer` (from the dialed child leg); completed < 3 s → `Too short`; completed ≥ 3 s → `Logged` (the transcript pass takes it). Processed T except for `Logged`. Rep = client id, only if an active employee. Entity via `lookupCallerByPhone` (whenever a number is found). Inbound sets `custevent_ctc_inbound`.
- **Outbound dialed number:** child legs from `Calls.json?ParentCallSid=` plus any child leg listed on the same page; the picked child first, then the other children (`to`, else `to_formatted`: 10 digits → `+1`, a leading `+` kept, `client:` / `sip:` ignored); then the parent leg's own `to` / `to_formatted`, unless it equals the config caller ID or a child's `from` (a rep's own caller ID is excluded only through a child's `from`). No number → log audit `CTC Recon outbound number not found` (parent `to`, `to_formatted`, child count).
- **Title:** outbound `No answer` → "No answer: <name or number>", or **"Call did not connect"** when no number is known. Others: "Missed call from …", "Inbound call from …", "Call to …" (fallback "unknown").
- **Date and call start:** `custevent_ctc_call_started` = Twilio `start_time` (RFC 2822 UTC) as ISO-8601 UTC. `startdate` = the local date of that start in the script user's time zone (`F/lib/ctc_time.js`: N/config `USER_PREFERENCES` `TIMEZONE`, else `COMPANY_INFORMATION` `timezone`, read once per execution; `format.format({ type: DATETIME, timezone })`, date part → `format.parse` DATE). **`starttime`, `endtime` and `timedevent` (Reserve Time) are never set**: reconciled Missed / No answer calls must not appear on the rep's calendar. A date failure logs `CTC Recon start date not set`; the UTC start is still stored and the call created.
- **Voicemail on an unanswered client leg:** for an inbound `Missed` leg with a parent, the parent call is read (from the page, else `Calls/<sid>.json`). Parent still live, or ended < 5 min ago → wait (stat `deferred`, the watermark holds at the leg's end). Else the parent's `Recordings.json` is listed; a voicemail = `call_sid` = parent, `source` ≠ `DialVerb`, status not `absent` / `deleted` / `failed`, not a completed 0 s recording. Voicemail → `Logged` + `custevent_ctc_voicemail` T, title "Voicemail from <name or number>", duration = recording length (stat `created.voicemail`). No voicemail → `Missed`.
- **PSTN parent legs without a client child** (caller hung up during the notice; unrouted number): Twilio `direction` `inbound`, no parent, `from` not a client, `to` a number whose VoiceUrl is our flow (`IncomingPhoneNumbers.json`, first 100, `voice_url` contains `/Flows/<custrecord_ctc_studio_flow_sid>`; read once per run, only when such a leg appears; no flow SID → no parent pass). A client child on the page or from `Calls.json?ParentCallSid=` → left to the child leg. Else `Missed`, or a voicemail when the parent has a voicemail recording. Stores the parent SID; deduped on the parent SID and every child SID. Owner: the number's primary rep (`loadRoutes`), else the fallback owner. Flow numbers / routes not readable → those legs wait (error, watermark held).
- **Owner and fallback:** client legs: the client id when it is an active employee; an inactive or unknown numeric id → the fallback owner (`custrecord_ctc_fallback_owner`) when it is an active employee; else skipped (as before). A non-numeric identity is skipped. Skipped calls get no Phone Call; besides the per-call audit row, each run with skips logs one audit `CTC Recon skipped calls — no owner` (`skipped=<n> fallbackOwner=<id or none> callSids=<up to 20>`) (2026-11-03).
- **Watermark** `custrecord_ctc_recon_watermark` (ISO UTC). Moves only after a complete run, to now − 5 min, never past a call whose create failed or that waits. **Pin cap** (2026-11-03): a failed call holds the watermark only while it ended less than `MAX_PIN_MS` (6 h, about 24 runs) ago; an older failing call is logged (`CTC Recon call dropped — failed too long`, with the SID), counted as `dropped`, and no longer holds it (before: up to 7 days, re-reading the whole window every run). Calls that wait (deferred voicemail) still hold it. Next run starts 15 min before it, never more than 7 days back. **First run: 7-day backfill.**

**Governance.** Runs in its own deployment `customdeploy_ctc_ss_poll_recon` (§6), so Phases A–C no longer use up its budget (before, Phase C could stop at 1000 units left, under the 2000 Phase D needs to start). Starts only with ≥ 2000 units left; stops before the next page or call below 1000; at most 5000 units and 200 pages per run. About 70 units per created call, plus 10–20 once per run for the time zone. A missed inbound leg adds a recordings GET (10) and maybe the parent call GET (10); a PSTN parent leg adds the child GET and the recordings GET (20); the flow numbers + routes cost 20 once per run.

**Open gaps.** Not live-tested. New statuses are not yet shown in the UI (§13). Live check pending: the parent-leg `to` of a TwiML App client call; `startdate` and the list time match the rep's time zone; voicemail cases (rang-and-not-answered, unrouted, hung up during the notice).
